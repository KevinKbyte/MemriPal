# 0031: Capacitor Android shell over a PWA; the web URL stays for judges

Status: Accepted
Date: 2026-10-31
Source: MEM-063 (`.claude/spec-cache/memripal/references/spec-3.md`); Kev (2026-10-31): Capacitor, Android first, over a
PWA. Supersedes in part minor decision D13 ("native Android deferred") in [README](README.md).

## Context

MemriPal is a phone-first flow (photo capture, spoken recall) served from Cloud Run (ADR
[0010](0010-cloud-run-hosting.md)). Judges use the public web URL, which must keep working unchanged. D13 rejected a
service worker (stale-deploy risk) and deferred native Android. A store-installable app needs a native wrapper; the
server is stateless (ADR [0003](0003-stateless-backend-client-state.md)), so a shell only has to ship the static UI and
call the API.

## Options considered

Chosen option first.

- (a) Capacitor 8 shell (`@capacitor/cli`/`core`/`android` ^8.6.0): `static/` bundled into `www/`, loaded in the
  WebView over `https://localhost`, API calls cross-origin to Cloud Run.
  Pros: real APK, installable and later Play-listable; same `static/` code, no fork; no service worker, so no
  stale-deploy cache; native plugins (camera, mic) available later; iOS can follow with the same `www/`.
  Cons: cross-origin API needs CORS on the server; APK build needs JDK + Android SDK; a second CSP (meta) for the
  bundle; a bundled UI can lag the server until rebuilt.
- (b) PWA (manifest + service worker) on the existing origin.
  Pros: no toolchain; same origin, so no CORS and one CSP; installs from the browser.
  Cons: the service worker is the stale-deploy risk D13 rejected; no store listing; weaker native camera/mic access
  on Android WebAPK; iOS install is manual.
- (c) Capacitor with `server.url` pointing the WebView at the Cloud Run URL.
  Pros: no CORS, no bundle drift.
  Cons: a remote page in a native shell (offline blank screen, store-review risk); `tests/test_mobile_shell.py`
  forbids it.

## Decision

Option (a), specified as MEM-063. `scripts/build_mobile_web.mjs` (`npm run build:mobile`) copies `static/` minus tests
into the gitignored `www/`, writes `www/static/runtime_config.js` with the `MEMRIPAL_API_BASE` origin, and injects a
native CSP meta whose `connect-src` is `'self'` plus that origin. `static/api_base.js` is the single owner of the API
base: `''` on the web, so the judges' URL is byte-for-byte unchanged in behaviour. `android/` is generated by
`npx cap add android` and committed.

## Why this over the others

Only (a) gives an installable Android app without the service-worker staleness D13 rejected and without a remote page
inside the shell. (b) reintroduces the rejected risk for a weaker install; (c) is a browser tab in an APK.

## Consequences

- CORS pending: `src/memripal/cors.py::add_cors` (exact origin allowlist from `MEMRIPAL_CORS_ORIGINS`, default
  `https://localhost`, `capacitor://localhost`; never `*`, no credentials) is tested but intentionally not wired into
  `create_app` (item 122, follow-up). Until it is, the APK cannot reach the API.
- APK toolchain: building the APK needs a JDK and `ANDROID_HOME`; Capacitor commands run with `CI=1` to skip the
  telemetry prompt that otherwise hangs non-interactive runs.
- CSP: the web CSP (MEM-042, `security_headers.py`) is unchanged and has no `connect-src`; the bundle carries its own
  meta CSP. `MEMRIPAL_API_BASE` must be a bare https origin; hosts outside `^[a-z0-9.-]+$` or bracketed IPv6 are
  refused before `www/` is cleaned, so a `"` or `;` cannot break out of the meta attribute.
- The bundled UI only updates on rebuild + reinstall; server API changes must stay backward compatible with shipped
  APKs.
- iOS is not built; `capacitor://localhost` is already in the default CORS list.
