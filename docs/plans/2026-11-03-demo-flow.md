## S1 Mount station route. MEM-083 (ready)

- Mount `src/memripal/routes_station.py` `POST /station` in `src/memripal/app.py`.
- CRITERIA: (1) TestClient `POST /station` returns 200 on a valid photo; (2) 4xx on a bad one.
- SIGNALS: none.

## S2 Routing + geocode. MEM-084, ADR 0046 (ready)

- `scripts/build_walk_graph.py`: one Overpass bbox query, retry, tested against a recorded response -> committed
  compact walk graph + named-POI JSON (< 1 MB). <!-- claim-exempt: planned -->
- Pure JS module: A* (haversine); geocode (normalized fuzzy match + aliases incl. "kendall/mit t" and "meta office" =
  42.36554,-71.0809); snap to the largest component; honest straight-line fallback.
- CRITERIA: (1) golden A* Kendall T -> 100 Binney within 40 m of the `DEMO_ROUTE` polyline (`static/demo_route.js`)
  and 600-750 m long; (2) every demo phrase resolves; (3) a miss returns >= 1 suggestion; (4) the fallback result is
  flagged.
- SIGNALS: one live Overpass fetch at build time.

## S3 Auto-loci + swap. MEM-085, ADR 0047 (ready)

- Pure `candidates(polyline, pois)`: 30-50 m, dedupe, rank, even spacing, ordered along the route.
- `static/route_store.js` swap/add/undo; keys `candidate:osm:<osm_id>` / `candidate:st:<station_id>`; no photo loss;
  `MAX_STATIONS` = 8.
- CRITERIA: (1) the Kendall route gives >= 6 candidates in route order; (2) swap round-trips `photo_ref`; (3) undo
  restores; (4) backup v2 export unchanged.
- SIGNALS: none.

## S4 Per-locus photo upload from the routes list. MEM-086 (after S1)

- CRITERIA: (1) upload sets `photo_ref` on the right station; (2) it survives a reload; (3) a photo-less station
  shows the add prompt.
- SIGNALS: e2e upload step.

## S5 Memorize logic. MEM-087, ADR 0048 (ready)

- Client for `/split` notes mode; keyword edit -> `split_list`; `/associate` per (keyword, station); client-side
  mnemonics; Jaccard + capacity recommendation with a reason; MemorizeItem `list:<id>` + backup `lists[]`;
  Deconstruct checkbox dependency rules.
- Record Spark fixtures for the 6-technique text; test that every template digest has a fixture.
- CRITERIA: (1) 6 keywords from the demo text; (2) edited keywords re-split with 0 model calls; (3) the
  recommendation picks a route with >= 6 free stations and shows a reason; (4) a fixture-mode run makes 0 live calls.
- SIGNALS: one live Spark record run (`scripts/run_live.ps1`, `META_API_KEY`).

## S11 Stretch 1: Memri assistant. MEM-093, ADR 0053 (after S6, S7)

- Chat box that runs the demo path on request (Kev). Muse Spark (`chat_json`, strict `json_schema`) only turns the
  request into an action plan. Allowed steps: `search_route{from,to}`, `accept_loci{count}`, `swap_locus`,
  `deconstruct{text, keywords, mnemonics, associations}`, `recommend_route`, `start_recall`.
- The client runs each step through the same S2-S5 pure modules; each step shows on screen and can be stopped or
  edited; the model never writes to the store directly.
- Photos stay manual (Kev): no photo step. After `accept_loci`, pause at each station without a photo, prompt via the
  S4 upload UI, then continue.
- Fixture mode replays a recorded plan for the demo prompt.
- ADR 0053 after an adversarial pass at slice start. <!-- claim-exempt: planned -->
- CRITERIA: (1) "walk me from Kendall T to the Meta office and help me memorize the 6 study techniques" yields a
  schema-valid plan reaching the same end state as the manual e2e path; (2) any invalid or unknown step is rejected
  with 0 store writes; (3) 0 photo writes come from the plan; (4) a fixture-mode run makes 0 live calls.
- SIGNALS: one live Spark record run.
