## Interface collisions (flagged)

1. `ModelBackend.segment(photo_sha, phrase, attempt)` / `spark_json(photo_sha, subject, attempt)` carry no image
   bytes, prompt or schema, so `MetaBackend` cannot make a live call through them (D5 stateless: the photo arrives
   per request). Root problem (C1 eval): the seam is a replay interface keyed by cache identity, not a call
   interface. Resolution: S2.3a `ModelRequest` carries image, prompt template, gen params and schema; `CacheKey` is
   derived from it; positional MEM-003 `segment()`/`spark_json()` become thin shims. **Superseded:** "S2.3 adds
   keyword-only request fields; FixtureBackend ignores them; item 5 first" -- item 5 is now S2.3a itself.
2. Import cycle: meta_client.py imports `MissingApiKey` from backend.py. `MetaBackend` must import `MetaClient`
   inside `__init__` (or `select_backend`), never at backend.py module top.
3. `PHRASE_SCHEMA` / `PHRASE_PROMPT` / `_reask_prompt` live in probe.py (being edited on s1-voice-probe). S2 imports
   them from probe.py unchanged; moving them to a prompts module is a post-merge refactor, not S2 scope. Item 5's
   "PROMPT_VERSION derived from prompt templates" must include these three.
4. `keep_loci` (MEM-007) keeps ONE box per phrase; D14 needs several same-type boxes. S2.2 adds a new
   `select_loci` beside it; `keep_loci` and the probe stay as-is (probe keeps measuring the S1 rule).
5. Fixture keys use the sha256 of the PROCESSED photo bytes (what Meta sees). The committed synthetic fixtures are
   keyed by the raw `fixtures/demo/photo.jpg` sha; S2.6 regenerates them through `process_upload`. A Pillow upgrade
   can change processed bytes: S2.6 pins the processed demo sha in a test so drift fails loudly, not as a silent
   FixtureMissing. AMENDED (C1 Decision): the sha is derived inside `ModelRequest` (`sha256(image_jpeg)`), never
   caller-supplied. Re-encoding is non-deterministic (demo photo at q90: 4 shas over 4 rounds), so S3/S4 must
   re-validate the client-returned processed photo with S2.1 `validate_processed()` (never re-encodes).
6. FastAPI `UploadFile`/`Form` need `python-multipart` (not a dependency). `/loci` reads the raw request body with
   `Content-Type: image/jpeg|image/png|image/webp` instead: no new dependency. Read via `request.stream()` with a
   running byte cap, never `request.body()` (C1 Decision).

### S2.1 Image intake (MEM-012) -- parallel-safe: YES (new files only)

Files: `src/memripal/imaging.py` (new), `tests/test_imaging.py` (new).
Interface:
- `MAX_UPLOAD_BYTES = 15 * 1024 * 1024`, `MAX_PIXELS = 40_000_000`, `MAX_SIDE = 8000`, `LONG_SIDE = 2048`.
- `class ImageRejected(ValueError)` with `.status: int` (413 too big, 400 otherwise) and a short reason code
  (`too_large`, `empty`, `bad_magic`, `pixel_bomb`, `decode_error`).
- `sniff(data: bytes) -> str` -> "jpeg" | "png" | "webp" from magic bytes (`FF D8 FF`, `89 50 4E 47 0D 0A 1A 0A`,
  `RIFF....WEBP`), else ImageRejected("bad_magic").
- `process_upload(data: bytes) -> Processed` where `Processed` = frozen dataclass(jpeg: bytes, width: int,
  height: int, sha: str). Order: empty -> size cap -> magic -> `Image.open` lazily -> check `w*h` and sides from
  the header BEFORE `load()` -> `ImageOps.exif_transpose` -> convert RGB -> downscale long side to 2048 (never
  upscale) -> re-encode JPEG quality 90 with no EXIF/ICC/comment -> sha256 hex. Any Pillow decode error
  (`UnidentifiedImageError`, `OSError`, `DecompressionBombError`, `SyntaxError`) -> ImageRejected("decode_error").
- `validate_processed(data: bytes) -> Processed` (C1 Decision; for S3/S4 re-validating the client-returned photo):
  same empty/size/magic/header checks, then must be JPEG, carry no EXIF APP1, long side <= `LONG_SIDE`; returns
  `Processed` over the INPUT bytes (`jpeg is data`, `sha = sha256(data)`), never re-encodes. Else ImageRejected
  (`not_jpeg`, `has_exif`, `too_big_side`, plus the shared codes).
Failing tests first:
- orientation-6 JPEG (built in tmp_path with `Image.Exif()[0x0112] = 6`, 300x100) -> processed 100x300 (dims
  swapped), output has no `Exif\x00\x00` APP1.
- 5 rejections: 15 MB + 1 byte (413), bad magic (`GIF89a...`), zero-byte, non-image (`b"hello"`), pixel bomb (PNG
  header declaring 9000x9000 in a < 1 KB file -> rejected without decoding).
- 4000x3000 -> 2048x1536; 800x600 stays 800x600; same input twice -> same sha (determinism).
- `validate_processed(process_upload(x).jpeg)` returns byte-identical jpeg and the same sha (no-reencode 1/1);
  PNG, EXIF-bearing JPEG, 3000 px long side -> rejected with their codes.
Checkpoint: `uv run pytest tests/test_imaging.py -q` green; rejections 5/5, orientation 1/1, no-reencode 1/1.

### S2.2 Locus selection (MEM-013) -- parallel-safe: YES (new files only; reuses probe_metrics read-only)

Files: `src/memripal/loci.py` (new, pure functions), `tests/test_loci_select.py` (new).
Interface:
- `Locus` frozen dataclass(n: int, label: str, phrase: str, box: Box, outline: list[tuple[int, int]]).
  `label` = short label (head noun = last word of the phrase, lowercased, positional prefix for duplicates);
  `phrase` = long phrase sent to SAM; `outline` = the 4 bbox corners (rectangle; mask outlines deferred, Ledger
  "rectangles first").
- `sanitize_box(box: Box, img_w: int, img_h: int) -> Box | None`: scale via `scaled_to`, reject unless
  0 <= x1 < x2 <= img_w and 0 <= y1 < y2 <= img_h (hostile-response guard: out-of-frame and absurd ints dropped).
- `select_loci(per_phrase: dict[str, list[Box]], img_w, img_h, *, min_loci=10, max_loci=12,
  spacing=0.05) -> list[tuple[str, Box]]` in this order: (1) every valid box of every phrase passes the area
  filter (0.5%..40%, inclusive, same integer math as keep_loci); (2) per phrase the largest is primary, the rest
  are spares; (3) IoU > 0.5 dedupe over primaries in descending area; (4) spacing collapse: centroid distance
  < spacing * image diagonal -> keep the larger; (5) D14: only while fewer than `min_loci` remain, add spares
  (largest first) that pass the IoU and spacing checks; (6) cap to `max_loci` by area.
- `disambiguate(selected) -> list[tuple[str, str, Box]]` -> (label, phrase, box): a head noun appearing k >= 2
  times gets positional labels by centroid x: k=2 "left/right", k=3 "left/middle/right", k>3 "<noun> 1..k"
  left to right. Phrase for SAM stays the original phrase.
- `route_order(items, img_h) -> list[...]`: row-aware: sort by centroid y; a new row starts when centroid y exceeds
  the current row's first centroid y by more than 10% of img_h; rows top to bottom, left to right by centroid x
  within a row; numbered n = 1.. in that order.
Failing tests first:
- 3x "book" (one phrase, 3 valid separated boxes) with 7 other phrases -> 10 loci incl. "left book", "middle book",
  "right book" (1/1); with 8 other phrases -> 10 loci, 2 books (spares stop at 10, sub-decision 2); with 12 other
  phrases -> at most one book (spares unused when primaries >= 10).
- spacing: two phrases with centroids 3% of the diagonal apart -> 1 kept (the larger); 6% apart -> 2 kept (1/1).
- ordering: 2 rows x 3 boxes with jittered y (within 10%) -> n=1..6 top-left to bottom-right (1/1).
- hostile: box with x2 > img_w, negative x1, x1 == x2, w=0 frame -> dropped; 13+ survivors -> exactly 12.
Checkpoint: `uv run pytest tests/test_loci_select.py -q` green; 3x book 1/1, spacing 1/1, ordering 1/1.

Interface:
- `find_loci(backend, processed: Processed, *, workers: int = 6, deadline_s: float = 90.0,
  on_progress: Callable[..., None] | None = None) -> LociResult` where `LociResult` = frozen
  dataclass(loci: list[Locus], phrases: list[str], reask_used: bool). Steps: spark_json subject "phrases"
