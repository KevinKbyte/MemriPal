## Recon facts (dev.meta.ai/docs; Finisher re-verified 2026-10-26 the items marked V, rest from Sonnet recon)

- Model API: https://api.meta.ai/v1, `Authorization: Bearer`, OpenAI-SDK compatible (Chat Completions, Responses).
- Muse Spark: muse-spark-1.3 standard $1.25/$4.25 per 1M, 3000 RPM (`-contributor` cheap; Meta may train on prompts).
  V: `response_format` json_schema is constrained decoding ("not post-processing"); `strict` defaults false and ONLY
  toggles schema validation (strict subset: root plain object, `additionalProperties:false`, `required` lists every
  key, no allOf/oneOf, depth <= 10, no recursion). V: structured output is documented as combinable with image input.
- Muse Image: muse-image-1.0, POST /v1/images/edits. V: 1-10 input images (`images[]` with `image_url` data URL);
  `mask`/`input_fidelity` -> 400 `unsupported_parameter`; an edit "changes only what you ask for while keeping the
  rest intact"; `size` sets ASPECT RATIO only, returned dims "won't match the numbers exactly"; output webp (default)/
  png/jpeg as `b64_json` (default) or signed url; $0.01 per generated image; 503 = retry with backoff; 400
  `content_policy_violation` = do not retry. Latency and max input dims undocumented.
- SAM 3.1: `sam-3.1` via POST /v1/responses. V: ONE noun phrase per request ("to segment several object types, send
  several requests"); output is special-token text, "one box and one mask per match"; confidence score not
  documented on the overview page (`/docs/sam/segmenting-with-prompts` 404s; check the SAM overview + client-libs
  pages in S1). Parser `meta_sam_parser` (py). Open weights `facebook/sam3.1` gated, license "other".
- Official Rules: not published (prior-work policy unknown). Workshops Oct 27/28 noon ET, Oct 30; office hours mornings.

## Assumptions and design decisions

Assumptions (A) are facts we bet on; decisions (D) are choices the Finisher locks for the build.

- A1 RESOLVED 2026-10-26: Meta API key in hand (storage per D11); the no-key text below stays as the contingency if the
  key is revoked or unusable. Original: Meta API key arrives by Oct 28 EOD. Until then dev runs on hand-written synthetic fixtures in the documented
  formats. No-key fallback (Oct 28 EOD): Spark via any OpenAI-compatible host (Baseten Muse Spark Open if granted);
  SAM via a stub that returns 12 HAND-ANNOTATED boxes on Kev's real demo photo (`fixtures/demo/boxes.json`, ~30 min of
  work) so the video still shows the real photo and real associations; Image via canvas fallback only; README states
  it plainly. Local/Modal SAM 3.1 is NOT a fallback (gated weights, license "other", different output format).
- A2 SAM 3.1 returns >= 1 box (+ mask) for a noun phrase present in the image; several boxes -> keep largest area.
  `meta_sam_parser` installs on Python 3.13 (S1 check; else hand-parse the documented token text).
- A3 Spark honours json_schema + image input (docs-verified). Schema restated in the prompt (prompt-bench lesson);
  `strict:true` with a conforming schema (cheap validation); parse failure -> 1 retry, then typed error.
- A4 Muse Image edits the WHOLE processed photo (long side 1024, JPEG data URL) from a server-built prompt of the form
  "add <scene> at the <locus>; keep everything else exactly as is". Output is resized to the input dims. Docs say
  edits keep the rest intact; S1 measures it (mean abs pixel diff outside 1.5x bbox < 12/255 on 1024 px).
- A5 >= 10 loci from one photo is unverified (shelf-inventory 27 -> 11 was SAM 2.1 everything-mode on a stock photo).
  Spark lists 20-25 phrases; if < 10 survive filter + dedupe, one more Spark round asks for further objects excluding
  the kept ones. Measured on Kev's demo photo in S1.
- A6 Stack: Python 3.13 + FastAPI (uv), vanilla ES-module frontend served by the same app, pytest + node:test.
- A7 Rules hypothesis (until Official Rules publish): new code only; README lists what was built and names the three
  APIs; miniprojects not copied. KAVE COGS paraphrased and credited; none of Metivier's text copied.
- A8 Solo; Kev does outward-facing steps (GitHub repo, GCP project, Meta key, CV submission, video, Quest runs).
- A9 Workshops/office hours may change API facts; S1 api-notes is the single place such changes land.

- D1 Public deploy serves `fixture` mode by default (zero spend); live `meta` mode needs a passcode header (compared
  with `hmac.compare_digest`; shared only in the submission notes) plus server input caps and a per-instance call
  budget (documented as per-instance, max-instances=1). This OVERRULES the persisted-budget dissent: judges score
  from the video, so a public live endpoint is a courtesy, not a Goal input, and a GCS/Firestore counter is extra
  infra for no rubric value. Real photos always use Spark standard tier (contributor only on synthetic fixtures).
- D2 Scenes: three tiers, chosen at S1 by measurement, never at runtime by taste. Tier 1 (default) whole-photo Muse
  Image edit (A4), shown as the locus scene with the overlay zoomed to the bbox. Tier 2 (if A4 drift fails) crop edit
  (bbox + margin, min 512 px side) shown as a scene CARD beside the locus, no compositing. Tier 3 (any failure,
  fixture miss, content-policy 400, timeout) canvas overlay: outline, numbered pin, item label. v1's feathered-mask
  composite is DROPPED: an object mask clips the mnemonic imagery that sits around the object, and crop-edit seams
  mismatch the photo's style; tier 1 needs zero compositing code.
- D3 Two backend modes matching the committed interface: `meta` (live, write-through cache of raw response bodies) and
  `fixture` (replay only). Cache key = logical identity (method, processed-photo sha256, phrase|item, attempt n,
  PROMPT_VERSION), never raw request bytes or auth headers. Fixture miss -> typed `FixtureMissing`; UI falls back
  (tier 3 for scenes; last recorded attempt for associations).
- D4 Quiz is deterministic and makes zero live model calls: Spark writes `walk_cue` and `reencode_hint` per item at
  encode time (stored in the palace). The committed ask "Spark quizzes you" is honoured by Spark authoring every cue
  and hint; README states this. Grading = local fuzzy match (normalized Levenshtein ratio >= 0.8 or token-set
  match); max 3 attempts per item then reveal + mark missed (quiz always terminates). Re-review = session queue tail
  (fsrs-review lesson); no cross-day FSRS.
- D5 Backend is stateless. The client holds the processed photo and sends it (JPEG <= 2048 long side, <= 6 MB body)
  with every loci and scene request; every endpoint re-validates image bytes, dims and text caps and builds every
  model prompt server-side from validated fields (never accepts a raw prompt). Palace state lives in IndexedDB as
  structured records with scene images stored as Blobs (not b64 strings): 10 webp scenes at 1024 px ~ 2-3 MB total,
  far under browser quota. Saved per completed record (resumable). No accounts, no palace JSON import/export.
- D6 Route order = row-aware left-to-right by bbox centroid; user can reorder (arrow buttons) or drop a locus
  (confirm + Undo). Each locus: short label (head noun, for validation), long phrase (for SAM), bbox, outline.
- D7 Each of S2-S4 ships its own minimal UI panel so something is demoable every day; S5 is route review, resume
  and walk-view polish, not the first UI.
- D8 Spec-cache FEAT IDs (`.claude/spec-cache/memripal/references/spec.md`) kept per Kev's Covers-tag rule; secret
  scan is a regex pre-commit hook, not gitleaks.
- D9 Round 2 adversaries skipped: round 1 converged (5 lenses, all accepted/partial), and the Finisher re-verified
  the load-bearing API claims against live docs instead.
- D10 Cut line if behind on Oct 31 EOD: S7 then S9 are dropped, in that order; S0-S6 + S8 are never cut.
- D11 Key custody (key in hand 2026-10-26): stored outside the repo, DPAPI-encrypted at `~/.secrets/meta-api-key.dpapi`.
  Only Kev-run live-mode launches decrypt it, into the child process env only (never a file, `.env`, or log). Claude
  sessions run `fixture` mode and must never read, decrypt, or print the key. Deploy (S7) uses Secret Manager instead.

## Rejected alternatives

- Full TS stack: weaker image processing; Kev's recent work is Python.
- Server DB + accounts: unneeded for a single-user demo; auth surface.
- Model-graded quiz: nondeterministic and costly.
- Self-hosted SAM (local or Modal) in the main path or as no-key fallback: gated weights, license "other", different
  output format, HF approval latency; follow-up only.
- Persisted (GCS/Firestore) daily budget: judges score the video; passcode + fixture default already bound spend.
- Feathered SAM-mask composite of a crop edit: clips imagery around the object, seam/style mismatch (D2).
- Palace JSON import/export: XSS/tracking surface for no Goal value.
- Streaming scene generation over one request: complexity; per-scene requests with the photo re-sent are enough.
