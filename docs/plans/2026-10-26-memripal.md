## Recon facts (dev.meta.ai/docs; Finisher re-verified 2026-10-26 the items marked V, rest from Sonnet recon)

- Model API: https://api.meta.ai/v1, `Authorization: Bearer`, OpenAI-SDK compatible (Chat Completions, Responses).
- Muse Spark: muse-spark-1.3 standard $1.25/$4.25 per 1M, 3000 RPM (`-contributor` cheap; Meta may train on prompts).
  V: `response_format` json_schema is constrained decoding ("not post-processing"); `strict` defaults false and ONLY
  toggles schema validation (strict subset: root plain object, `additionalProperties:false`, `required` lists every
  key, no allOf/oneOf, depth <= 10, no recursion). V: structured output is documented as combinable with image input.
- Muse Image: muse-image-1.0, POST /v1/images/edits. V: 1-10 input images (`images[]` with `image_url` data URL);
  `mask`/`input_fidelity` -> 400 `unsupported_parameter`; an edit "changes only what you ask for while keeping the
  rest intact"; `size` sets ASPECT RATIO only, returned dims "won't match the numbers exactly"; output webp (default)/
  png/jpeg as `b64_json` (default) or signed url; $0.01 per generated image; 503 = retry with backoff; 400
  `content_policy_violation` = do not retry. Latency and max input dims undocumented.
- SAM 3.1: `sam-3.1` via POST /v1/responses. V: ONE noun phrase per request ("to segment several object types, send
  several requests"); output is special-token text, "one box and one mask per match"; confidence score not
  documented on the overview page (`/docs/sam/segmenting-with-prompts` 404s; check the SAM overview + client-libs
  pages in S1). Parser `meta_sam_parser` (py). Open weights `facebook/sam3.1` gated, license "other".
- Muse Voice Transcribe (Q1; docs https://dev.meta.ai/docs/speech-to-text/): `muse-voice-transcribe-1.0`, Bearer.
  File: POST /v1/asr/transcribe, multipart `request` JSON {mode:PUSH_TO_TALK, model, audioEncoding:WAV, optional
  keywords, languageBias} + `audio` part; WAV mono 16-bit PCM 16/24 kHz ONLY (webm/opus NOT accepted); 32 MB / 10 min
  per file. Realtime: wss://api.meta.ai/v1/asr/realtime, raw PCM16 LE mono 24 kHz (preferred) or 16 kHz, partial +
  final transcript events, 60 min session. $0.18/hour billed per second; 256 concurrent streams/tenant. No word
  timestamps, no confidence scores. Unverified until the S1 voice probe: key works on /asr, latency.
- Official Rules (hackathon.md section 4 + 7-8, read 2026-10-26): repo public (:88); team <= 4, solo ok (:90); demo
  shows ONLY hackathon-built work, clearly identified, else disqualification (:92, :94); judged on the 3-min video +

- D4 REWRITTEN Q1 2026-10-26 (Kev): recall is SPOKEN and the match step is deterministic code with zero LLM calls.
  Spark writes `walk_cue` and `reencode_hint` per point at encode time (stored in the palace); README says Spark
  authors every cue/hint and Muse Voice Transcribe hears you. Flow: "Hide palace" toggle (CSS blur of scenes +
  labels); browser captures PCM16 mono (24 kHz preferred, 16 kHz ok) via AudioWorklet and streams it to
  passcode-gated `/recall/audio`, which relays to the Muse Voice Transcribe realtime WebSocket (key stays server-
  side) and returns partial/final transcript TEXT only; the palace's short labels go as `keywords`. Fallback
  transport: client-encoded WAV clips (~8 s, 2 s overlap) to /v1/asr/transcribe via the same endpoint. Client
  appends to a running transcript and runs the local matcher: sliding token window vs each point's `source_quote`
  and short label, normalized Levenshtein/token-set ratio >= 0.8 on any window OR key-term coverage >= 60%; once
  matched stays matched; matcher returns the matched transcript span. No LLM in the match step (no paraphrase
  leniency, no voice prompt injection). Matched loci glow live with a "listening..." indicator; end screen =
  got/missed + manual "mark got it" override + re-recite of misses only (re-queue-misses goal kept). Fallbacks: mic
  denied/unsupported -> typed box feeding the same matcher; `fixture` mode replays a recorded transcript chunk
  timeline offline, labelled "replay of a recorded session". Security: chunk/frame <= 1 MB server cap, session
  <= 5 min, WAV clips validated by RIFF/WAVE header + mono/16-bit/16|24 kHz (webm/opus rejected; raw PCM frames by
  declared format + size), audio never written to disk or logs, audio seconds in the D1 budget. Optional: Baseten
  Muse Spark Open audio behind a D12 flag (credits granted, $100 (Kev 2026-10-26)).
  Superseded by D4 (Q1): the typed walk quiz as the primary path (now the mic-denied fallback), max-3-attempts
  reveal loop (replaced by got/missed + re-recite), and the AMENDED 2026-10-26 one live Spark call per answer
  attempt with local-LLM fallback (live grading would put an LLM in the match step).
- D5 Backend is stateless. The client holds the processed photo and sends it (JPEG <= 2048 long side, <= 6 MB body)
